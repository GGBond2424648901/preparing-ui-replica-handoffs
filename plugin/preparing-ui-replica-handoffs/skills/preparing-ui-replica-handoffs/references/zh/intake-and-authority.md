# 输入与权威顺序

sectionId: intake

## 最小输入

ruleId: IA-001

开始前必须解析并记录：只读设计图片目录、独立交付输出目录、设计版本、交付语言（默认 `zh-CN,en-US`）。输出目录不得位于输入目录内部，也不得复用未被本工具管理的目录。

ruleId: IA-002

可选输入包括产品目标、用户角色、模块清单、正式需求、路由、数据/权限说明、品牌资产、目标技术栈、目标平台、布局策略、批准的页面/状态/响应式变体、浏览器/视口/DPR/Locale/时区/主题/字体环境，以及 Git 仓库与允许路径。缺少时登记 `gapId`，不得静默猜测。

sectionId: source-immutability

## 源文件只读边界

ruleId: IA-003

原始设计目录是证据源：只能读取、哈希和复制。禁止原地重命名、移动、删除、转码、压缩、覆盖或添加联系表。整理后的英文编号名只用于 `assets/designs/<design-version>/` 副本。

ruleId: IA-004

扫描时记录相对源路径、MIME/格式、字节数、像素尺寸、SHA-256、重复组和来源集合哈希。冻结前后重新计算；变化即失败，不生成可信设计锁。

sectionId: authority

## 冲突权威顺序

ruleId: IA-005

冲突时固定采用：用户最新明确修正 > 已批准参考图 > 已批准资产 > 已验证产品资料 > 正式需求 > 当前实现 > 已记录假设。每次冲突记录候选证据、胜出项、原因和影响的合同 ID；不得以“看起来合理”覆盖更高权威证据。

ruleId: IA-006

图像是视觉权威，不自动成为业务规则权威。设计稿示例数据标为 `sample`；它不能证明 API、计算公式、权限、数据真实性或异常状态。

sectionId: evidence

## 证据等级与缺口

ruleId: IA-007

所有关键结论使用统一等级：`direct`（直接可见）、`derived`（由可见事实计算并写明推导）、`candidate`（待确认复用/映射）、`approved`（已由用户或权威资料批准）、`unknown`（没有足够证据）。禁止把 `candidate` 或 `unknown` 表述成事实。

ruleId: IA-008

未解决项必须有唯一 `gapId`、严重度、受影响对象、证据位置、决策人、状态和解决条件。`blocker`/`major` 未解决时交付不得标为完成。

sectionId: copy-and-data

## 文案与数据

ruleId: IA-009

清晰文字原样照录；已确认文案引用正式资料；无法辨认且仅在布局需要占位时，可写长度相近、符合业务语境的推断文案，但必须标 `inferred`、记录原图坐标/裁图和 `gapId`。禁止照抄乱码，也禁止把推断文案标成 `direct`。

ruleId: IA-010

每个数据项分类为 `sample`、`product-confirmed`、`derived` 或 `unknown`，并记录格式、长内容边界及脱敏要求。不得从样例值推断后端契约。

sectionId: intake-gate

## 启动门禁

ruleId: IA-011

执行生成前先报告将读取的源、将写入的输出、源图数量、设计版本、语言和已知缺口。若路径关系不安全、源为空/损坏或输出所有权不明确，停止并给出稳定诊断。

sectionId: target-platform

## 目标平台与布局策略

ruleId: IA-012

本技能默认准备 `desktop-web` + `desktop-hybrid-elastic` 合同；若用户明确指定其他平台，或设计图直接证明移动端/原生桌面端，则以更高权威输入覆盖默认值并记录证据。桌面默认值只能确定实施优先级，不能伪造成截图直接证据。

ruleId: IA-013

桌面端合同必须区分固定/粘性 Shell、流式或有界流式工作区、受最小/最大尺寸约束的组件、页面级滚动和功能型区域滚动。移动端单列、隐藏导航或大范围重排必须作为独立 `variantId`，只有直接证据或明确批准才能建立。

sectionId: reference-roles

## 参考资料角色识别

ruleId: IA-014

视觉检查的第一轮只做角色识别：页面参考图、UI 设计语言图、组件板、品牌板、交互状态板、动效参考、装饰背景、内容资产或 unknown。文件名只能作为候选线索，不能替代视觉证据；每项使用稳定 `REF###` 并记录作用域与权威类别。

ruleId: IA-015

UI 设计语言图可以成为跨页面视觉权威，但必须逐条限定适用范围。全局原则不能覆盖页面中更具体的直接证据；页面特例也不能反向污染全局 Token。继承、覆盖、例外和冲突分别记录。

sectionId: design-language-sets

## 多张设计语言图与标题证据

ruleId: IA-016

图片可见标题明确写有“UI 设计语言”“Design Language”“Design System”“视觉规范”或等价产品专名时，将标题文字及其坐标记录为直接角色证据，并立即把该图从页面候选中分离。使用多模态模型直接阅读画面，不依赖外部 OCR；文件名只能辅助定位，不能覆盖视觉标题。

ruleId: IA-017

设计语言图可以有多张。先按产品、版本、主题、模块和作用域组成一个或多个 `DLS###` 集合，再逐条建立 `DR###`。相同规则保留全部来源坐标；互补规则合并；主题/模块差异并存；只有明确版本证据才能标记覆盖；冲突写入 `DRC###`，未解决时禁止批准相关页面。

sectionId: evidence-graph

## 证据图谱与画布校准

ruleId: IA-018

用 `reference-relationships.json` 记录续页、细节、状态、变体、响应式、覆盖层、组件板、品牌板、重复、互补、覆盖和冲突关系。用 `viewport-calibration.json` 区分源图画布、真实 UI 视口、裁切偏移、缩放/DPR、完整内容范围、固定/粘性区域，以及注释、红线、尺寸标记、讲解文字、水印、浏览器外框和设备框；后者默认不得当成真实 UI 实现。

ruleId: IA-019

用 `design-inconsistencies.json` 记录 AI 生成稿或跨图出现的畸形图标、不可能透视、几何漂移、文案冲突、资产冲突和交互冲突。每项必须选择保留页面特例、规范化、重绘、推断文案或保持未解决，并记录胜出证据与验收影响。

sectionId: navigation-authority

## 导航权威与冻结

ruleId: IA-020

在逐页建设前，对所有参考图的导航逐项观察：标题、图标、顺序、父子层级、路由、选中态以及角色/权限可见性。把漏项、多项、标题差异、图标差异、顺序差异、层级差异、路由差异和权限差异登记到 `navigation-reconciliation.json`；形成唯一规范导航树并达到 `freezeStatus: approved` 后，页面才能批准。
