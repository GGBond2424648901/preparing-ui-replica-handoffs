# 组件与样式合同

sectionId: tokens

## 视觉 Token

ruleId: CS-001

从可见证据提取颜色、字体族、字号、字重、行高、字距、间距、圆角、边框、阴影、透明度、层级和动效。记录原始值、归一化 token、证据等级、来源页/区域和测量容差。

ruleId: CS-002

相近值不能为了“整洁”被强行合并。只有重复证据或批准才能建立全局 token；单页值保留页面作用域并标 `candidate`。

sectionId: shell

## 全局 Shell

ruleId: CS-003

定义导航、Sidebar、TopBar、面包屑、工作区、底栏、浮层根节点和通知层的尺寸、层级、滚动所有权及页面复用矩阵。逐项标明固定、流式、有界流式或内容固有宽度；常见固定 Sidebar 与弹性主工作区必须分别建模，不能把截图中的主内容宽度硬编码为全局上限并在宽屏留下意外空白。不同 Shell 类型使用不同 ID，不得用一个 Shell 解释全部页面。

ruleId: CS-004

Logo 必须记录正式资源相对路径、显示尺寸、留白、安全区、浅/深色版本、背景限制和使用位置。缺少正式资产时登记 `gapId`，禁止从截图裁切后冒充正式 Logo。

sectionId: registry

## 组件注册与复用

ruleId: CS-005

设计中出现时，组件注册表至少覆盖导航、卡片、按钮、输入、选择器、标签、表格、分页、图表、AI 对话、文件、工作流、Diff、日志、弹窗、抽屉、Toast、Tooltip、空状态和骨架屏。

ruleId: CS-006

每个组件记录 component ID、名称、作用域、结构 anatomy、尺寸、变体、状态、slot、内容边界、交互、可访问性、token、图标和使用页面；尺寸合同包含宽度模式、最小/基准/最大宽高、`flex-grow`/`flex-shrink` 或 Grid 轨道权重、换行阈值及溢出所有者。相似外观先标 `candidate`；结构和行为均一致并获批准后才共享。

sectionId: controls

## 控件精确规则

ruleId: CS-007

按钮记录高度、水平内边距、图标间距、圆角、字体、默认/hover/focus/pressed/disabled/loading/danger 状态及点击结果。未展示状态保持 `unknown` 或 `proposed`。

ruleId: CS-008

输入与选择器记录标签、占位符、前后缀、帮助/错误文本、字符/文件限制、聚焦边框、清空、搜索、多选、键盘和提交行为；不从单张静态图推断验证逻辑。

sectionId: data-components

## 数据与复杂组件

ruleId: CS-009

表格记录列顺序/宽度/对齐、表头、行高、固定列、排序/筛选、选择、展开、分页、空/加载/错误/长文本和横向滚动。示例行保持 `sample`。

ruleId: CS-010

AI 对话记录角色、气泡/消息块、Markdown/代码/引用、流式状态、停止/重试/复制/反馈、附件和错误；文件组件记录类型、大小、进度、预览、下载、失败和权限。未见能力不得补造。

ruleId: CS-011

工作流记录节点/端口/连线/画布、缩放/平移/选择、运行状态和面板；Diff 记录左右/行内模式、增删改标记、行号和折叠；日志记录级别、时间、来源、换行、筛选、复制、自动滚动和长内容性能。

sectionId: icons-assets

## 图标与资产映射

ruleId: CS-012

图标优先级为正式资产 > 已确认图标库精确名称 > 经批准候选。每个映射记录库、名称、版本（已知时）、尺寸、viewBox、线宽、填充/描边、颜色、坐标和适用状态。

ruleId: CS-013

图片、头像、插画、图表纹理和文件缩略图必须引用交付包相对路径并带哈希。正式 Logo/专有图形优先 SVG，普通图标使用锁定版本与名称的图标库，简单几何/材质使用 CSS，精确曲线/圆环/图表标记优先 SVG，高密度动态图形可用 Canvas，环境插画可用本地光栅图。禁止绝对路径、远程热链、Emoji 或字体字符冒充图标。

ruleId: CS-013A

登录页、Hero 和环境场景可使用一张完整的纯装饰背景，并在其上用真实 DOM 实现 Logo、标题、表单、按钮、错误、动态数据和交互。必须记录背景来源/生成状态、原始尺寸、比例、适配方式、焦点、安全区、裁切和响应式变体。含控件、文案、数据或状态的整页截图不得作为交互实现；普通业务页仅可在有证据时局部采用装饰背景。

sectionId: accessibility

## 可访问性与长内容

ruleId: CS-014

记录语义角色、可访问名称、焦点顺序、键盘动作、对比度风险、减少动效和屏幕阅读器反馈。设计未展示时标为实施要求或 `proposed`，不要伪装成视觉事实。

ruleId: CS-015

为所有文本和数据组件定义最短/最长/空值/多语言/换行/截断/Tooltip/滚动策略。不得通过缩小字号或破坏列比例掩盖长内容。

sectionId: elastic-sizing

## 弹性尺寸与缩放

ruleId: CS-016

对 Dashboard、卡片组、表格区、图表区和多列工作区记录父容器可用宽度、列数、轨道公式（如比例或 `minmax()`）、间距、每列最小/基准/最大宽度及剩余空间分配。宽屏优先保持设计中的列数、顺序和视觉层级，并按合同让可伸展列或卡片吸收空间；没有证据不得任意新增列，也不得保留造成大面积死空白的固定内容宽度。

ruleId: CS-017

浏览器缩放按“有效 CSS 视口变化”处理，不把页面根节点或截图整体做视觉缩放。达到组件最小尺寸前允许按伸缩合同收缩；达到下限后依据证据换行、重排或启用页面/模块/混合滚动。字体、图标、边框和间距继续使用合同 token，不能通过额外比例因子二次缩小。

sectionId: desktop-mixed-layout

## 桌面混合布局角色

ruleId: CS-018

每个 Shell、区域和组件必须登记桌面角色：`fixed-shell`、`flexible-workspace`、`bounded-content`、`scroll-surface` 或 `intrinsic`。Sidebar、TopBar、工具栏通常仅在证据支持时固定/粘性；主工作区负责吸收剩余空间；文本/表单内容可有界；表格、代码编辑器、流程图、画布和日志可作为专用滚动面。不得把同一种伸缩规则强加给所有角色。

ruleId: CS-019

桌面页面默认只有一个主要纵向滚动链；模块滚动只用于固定高度或二维/连续功能面，并记录轴向、边界、滚动链、滚轮转交和可达性。宽屏时通过有界列、最大行长和组件上限避免内容过宽；窄桌面时到达最小尺寸后优先滚动，只有获批变体才大范围重排。

sectionId: design-language-authority

## UI 设计语言权威图

ruleId: CS-020

输入图先按页面参考图、UI 设计语言总览、组件板、品牌板、交互状态板、动效参考和装饰背景分类。设计语言图中的原则、材质、Token、Shell、图标、图表、动效与禁止项必须进入独立的 `UI设计语言.md` 和 `reference-inventory.json`，不得混入页面清单后丢失全局权威含义。

ruleId: CS-021

每条共享设计语言规则记录来源 `referenceId`、裁图/坐标、适用范围、例外、证据等级和受影响页面/组件。页面先继承适用规则，再叠加页面直接证据；用户修正和页面专属设计优先于共享规则，冲突必须登记。

sectionId: micro-visual-contract

## 微视觉合同

ruleId: CS-022

每页可见的图标尺寸/描边、Logo 比例与留白、装置/圆柱比例、曲线控制点、圆环外径/内径/起止角、边框、四角半径、阴影、透明度、渐变停止点、Blur、裁切、Mask、层级和溢出都必须以 `micro-visual-contract.json` 建档，不能只写“大致相似”。

ruleId: CS-023

每个微视觉特征必须绑定页面、区域、来源 `referenceId`、Bounds、渲染策略、响应式行为和几何/颜色/透明度容差，并加入 `diff-regions.json` 的特征级 reference/current/overlay/diff 验收目标。

sectionId: named-visual-language

## 主体视觉语言的机器化拆解

ruleId: CS-024

若设计语言图写明“苹果风格”“磨砂质感”“高级玻璃”“透明磨砂”“玻璃拟态”或其他主体描述，不得只抄形容词。逐条拆为背景与承载层、backdrop blur、前景 blur、透明度、色调/饱和度、内外高光、半透明边框、环境阴影、噪点/纹理、层级、与背景的对比条件和禁止组合；每条 `DR###` 保留来源坐标，并映射到 materials/backgrounds/blur/opacity/borders/shadows/layers Token。

ruleId: CS-025

主体视觉语言必须向所有控件继承。按钮、图标按钮、搜索、输入框、文本域、单选、多选、开关、下拉、多选标签、Tab、分页、表格操作、导航项、卡片、弹窗、抽屉和 Tooltip 的默认、hover、focus-visible、pressed、selected、disabled、loading、error 状态，都要列出 `styleTokenRefs`、`sourceRuleIds`、局部覆盖和视觉验收目标。禁止出现背景采用高级玻璃，而按钮或搜索仍为无关默认组件库风格的割裂实现。

sectionId: motion-contract

## 动效与微交互合同

ruleId: CS-026

每个有证据的 Hover、Focus、Pressed、Selected、展开/收起、进入/退出、加载、滚动、拖拽或状态切换使用 `MOT###`：记录目标、触发、起止视觉、动画属性、时长、延迟、缓动、transform-origin、层级、指针、焦点、状态帧来源和 Reduced Motion 降级。仅有静态图且没有文字、状态板或多帧证据时，不得把常见动效标为直接事实，只能标 `candidate`/`unknown` 并登记缺口。

ruleId: CS-027

微交互动效必须服务主体材质语言：玻璃高光、边框亮度、阴影深度、微位移、透明度或背景模糊的变化使用同一 Token 和规则级联。禁止无证据的大幅弹跳/缩放、布局抖动、改变组件尺寸导致邻接内容跳动，以及只支持鼠标而没有等价 focus-visible 状态。

sectionId: semantic-visual-encoding

## 语义颜色、状态与等级编码

ruleId: CS-028

将优先级、流程状态、证据等级、反馈、审批、风险、同步/网络、在线状态、权限、AI 运行态、数据新鲜度和校验结果拆成独立 `SEM###` 维度。每个可见值使用 `SEMVAL###` 记录编码、双语标签、业务含义、胶囊/圆点胶囊/圆点标签/徽标形状，以及文字、底色、边框、圆点和图标五类颜色。P0/P1/P2、待验收/草稿/进行中/阻塞/待审核、A/B/C/未评级等必须按原图分别测量，不能只写“红/黄/蓝状态”。

ruleId: CS-029

逐值测量高度、最小宽度、水平/垂直内边距、文字与圆点间距、圆角、边框宽度、圆点直径、图标尺寸、字体、字重和行高，并登记默认、hover、focus-visible、pressed、selected、disabled、loading。主体材质可影响承载层，但语义识别和对比度优先；设计稿使用浅色实底胶囊时，不得为追求玻璃感擅自改成透明玻璃。

ruleId: CS-030

颜色相同不代表语义相同：优先级 P0 的红色、错误反馈红色和阻塞状态红色保持独立 Token 与含义，除非权威设计语言图明确要求统一。不同维度禁止互相推断顺序或状态；未展示的 P3、成功、离线、AI 失败等只能作为检查清单，不能生成正式值。每个页面通过 `semanticDimensionIds`/`semanticValueIds` 声明实际使用项，并在 `semanticTargets` 中做颜色、几何和对比度 Diff。
