# 组件与样式合同

sectionId: tokens

## 视觉 Token

ruleId: CS-001

从可见证据提取颜色、字体族、字号、字重、行高、字距、间距、圆角、边框、阴影、透明度、层级和动效。记录原始值、归一化 token、证据等级、来源页/区域和测量容差。

ruleId: CS-002

相近值不能为了“整洁”被强行合并。只有重复证据或批准才能建立全局 token；单页值保留页面作用域并标 `candidate`。

sectionId: shell

## 全局 Shell

ruleId: CS-003

定义导航、Sidebar、TopBar、面包屑、工作区、底栏、浮层根节点和通知层的尺寸、层级、滚动所有权及页面复用矩阵。逐项标明固定、流式、有界流式或内容固有宽度；常见固定 Sidebar 与弹性主工作区必须分别建模，不能把截图中的主内容宽度硬编码为全局上限并在宽屏留下意外空白。不同 Shell 类型使用不同 ID，不得用一个 Shell 解释全部页面。

ruleId: CS-004

Logo 必须记录正式资源相对路径、显示尺寸、留白、安全区、浅/深色版本、背景限制和使用位置。缺少正式资产时登记 `gapId`，禁止从截图裁切后冒充正式 Logo。

sectionId: registry

## 组件注册与复用

ruleId: CS-005

设计中出现时，组件注册表至少覆盖导航、卡片、按钮、输入、选择器、标签、表格、分页、图表、AI 对话、文件、工作流、Diff、日志、弹窗、抽屉、Toast、Tooltip、空状态和骨架屏。

ruleId: CS-006

每个组件记录 component ID、名称、作用域、结构 anatomy、尺寸、变体、状态、slot、内容边界、交互、可访问性、token、图标和使用页面；尺寸合同包含宽度模式、最小/基准/最大宽高、`flex-grow`/`flex-shrink` 或 Grid 轨道权重、换行阈值及溢出所有者。相似外观先标 `candidate`；结构和行为均一致并获批准后才共享。

sectionId: controls

## 控件精确规则

ruleId: CS-007

按钮记录高度、水平内边距、图标间距、圆角、字体、默认/hover/focus/pressed/disabled/loading/danger 状态及点击结果。未展示状态保持 `unknown` 或 `proposed`。

ruleId: CS-008

输入与选择器记录标签、占位符、前后缀、帮助/错误文本、字符/文件限制、聚焦边框、清空、搜索、多选、键盘和提交行为；不从单张静态图推断验证逻辑。

sectionId: data-components

## 数据与复杂组件

ruleId: CS-009

表格记录列顺序/宽度/对齐、表头、行高、固定列、排序/筛选、选择、展开、分页、空/加载/错误/长文本和横向滚动。示例行保持 `sample`。

ruleId: CS-010

AI 对话记录角色、气泡/消息块、Markdown/代码/引用、流式状态、停止/重试/复制/反馈、附件和错误；文件组件记录类型、大小、进度、预览、下载、失败和权限。未见能力不得补造。

ruleId: CS-011

工作流记录节点/端口/连线/画布、缩放/平移/选择、运行状态和面板；Diff 记录左右/行内模式、增删改标记、行号和折叠；日志记录级别、时间、来源、换行、筛选、复制、自动滚动和长内容性能。

sectionId: icons-assets

## 图标与资产映射

ruleId: CS-012

图标优先级为正式资产 > 已确认图标库精确名称 > 经批准候选。每个映射记录库、名称、版本（已知时）、尺寸、viewBox、线宽、填充/描边、颜色、坐标和适用状态。

ruleId: CS-013

图片、头像、插画、图表纹理和文件缩略图必须引用交付包相对路径并带哈希。禁止绝对路径、远程热链或把完整页面截图当作实现背景。

sectionId: accessibility

## 可访问性与长内容

ruleId: CS-014

记录语义角色、可访问名称、焦点顺序、键盘动作、对比度风险、减少动效和屏幕阅读器反馈。设计未展示时标为实施要求或 `proposed`，不要伪装成视觉事实。

ruleId: CS-015

为所有文本和数据组件定义最短/最长/空值/多语言/换行/截断/Tooltip/滚动策略。不得通过缩小字号或破坏列比例掩盖长内容。

sectionId: elastic-sizing

## 弹性尺寸与缩放

ruleId: CS-016

对 Dashboard、卡片组、表格区、图表区和多列工作区记录父容器可用宽度、列数、轨道公式（如比例或 `minmax()`）、间距、每列最小/基准/最大宽度及剩余空间分配。宽屏优先保持设计中的列数、顺序和视觉层级，并按合同让可伸展列或卡片吸收空间；没有证据不得任意新增列，也不得保留造成大面积死空白的固定内容宽度。

ruleId: CS-017

浏览器缩放按“有效 CSS 视口变化”处理，不把页面根节点或截图整体做视觉缩放。达到组件最小尺寸前允许按伸缩合同收缩；达到下限后依据证据换行、重排或启用页面/模块/混合滚动。字体、图标、边框和间距继续使用合同 token，不能通过额外比例因子二次缩小。
